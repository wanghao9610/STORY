# 路由 STORY 请求

> 本文件是 [`story.md`](story.md) 的中文对照版。运行时路由以英文原文件为准。

使用下表把硕士或博士学位论文工作流请求路由到恰好一个 STORY skill。涉及学位层级的 skill 从 `degree/profile.tex` 读取 `% degree_level: master|doctoral`；分流器不得猜测。

| Skill | | 用途 |
| --- | --- | --- |
| `story-chap-drafter` | | 以作者的学术声音起草或修改一个章节或一份前置/后置部分文件的内容，包括 `\cite` 放在何处 |
| `story-cite-auditor` | | 审计引用键、文献断言和参考文献条目规范性 |
| `story-clms-auditor` | | 审计数字、比较、学位贡献和来源锚点；怀疑某个数字有误时先找它 |
| `story-copy-editor` | | 润色一个章节、一份前置/后置部分文件或整篇论文（`full`）的读感——作者声音、术语、过渡、公式化表达——不改变事实、论断或引用；记录作者文风档案（`style`） |
| `story-defn-builder` | † | 根据已确认规则和论断构建答辩叙事与演示文稿 |
| `story-depo-packer` | † | 预检并冻结一个指定的归档包 |
| `story-evid-curator` | | 导入、登记、刷新或完整性检查证据 |
| `story-exam-reviewer` | | 模拟适合学位层级的评阅人或委员会评审 |
| `story-figs-designer` | | 构建一个由证据支持的学位论文图 |
| `story-flow-status` | | 汇报仓库状态并给出恰好一个下一步动作 |
| `story-outl-planner` | † | 把已确认总叙事转化为章节架构与章节简报 |
| `story-proj-adopt` | † | 安全接入已有硕士或博士学位论文草稿 |
| `story-refs-curator` | | 整理参考文献记录与阅读笔记；在正文中放置 `\cite` 归 `story-chap-drafter` |
| `story-revs-resolver` | † | 把收到的反馈转化为处理决定和可跟踪承诺 |
| `story-syns-coach` | † | 确认或修改论文级论证与贡献框架，或记录一项出版物复用或许可事实 |
| `story-tabs-builder` | | 构建一个由证据支持的学位论文表格 |

标有 † 的六个 skill 只能显式调用，因为每个都控制一项属于作者的论文级、里程碑或学校制度决定。通用 `/story` 分流器绝不启动它们，也绝不询问是否启动。而是写明该 skill、一句话理由，以及供作者自己敲下的准确 `/story-<name> <argument>` 命令（若建议的参与度不同于 `.env` 中 `INVOLVE` 解析出的级别，就在命令里写明 `involve=<level>`，规约 §8），然后停止。任务明确匹配时，可以选择其余十个 skill。

请求若是“朝一个目标跨多步推进——论文接下来需要什么就跑什么，直到达成”，不路由到单个 skill：给出准确的 `/story-auto <目标>` 命令，然后停止。由作者敲下它，是多步运行唯一的常设授权（规约 §8，Goal runs）；即便如此，标有 † 的 skill 也绝不启动：目标运行停在那里，并打印它的命令。

请求为空时选择 `story-flow-status`。若请求是没有 skill 负责的作者行动，例如 `degree/` 中的已确认事实（`degree_level`、委员会名单中的一行），就把它标为作者行动（规约 §8，Completion handoff），写明文件和字段，然后停止。否则，说明选中的 skill、选择它的一句话理由，并把原请求作为参数传入。未标记的 skill 应通过当前 harness 的原生 skill 机制启动，并使用该 harness 拥有的副本。如果两个 skill 同样合理，只问一个简洁问题，不要混合两者范围。一个需要两个负责方先后处理、又不是目标推进的请求，交给第一个；它的交接会写明第二个。绝不能绕过 skill，凭一般知识直接生成归它所有的产物。

状态、解释、审计或只评审的请求只授权交付该结果。路由时保持这一点：不要仅因为报告建议了某一步，就开始起草、编辑、导入或启动另一个写入型后续 skill。作者已经给出的明确授权在其声明范围内持续有效，不再重复询问；`AGENTS.md` §1 规定须先询问的选择在任何参与度下都要询问：只有作者对该问题的回答才构成授权，请求本身的措辞不构成授权（规约 §7 与 §8）。
