# 润色学位论文

首先完整阅读 `docs/mds/story-workflow/writing-workflow-conventions.md` 和 `docs/mds/story-workflow/human-writing-guide.md`。解析一个章节目标，或明确确认执行全文处理。读取存在的 `notes/style.md`，以及 `notes/notation.md`、`notes/story.md` 和相关提纲简报。读取风格档案指向且经作者确认的样本。普通润色不因风格档案缺失而阻塞；总叙事、符号表或提纲元数据缺失时，路由给负责创建它的 skill。

编辑前标记受保护内容：事实、数字、日期、引文、引用键、来源注释、论断与不确定性边界、技术区别和归属。改进句式、段落流动、路标、术语、缩写首次出现和跨章节一致性。依据模式组合和功能诊断公式化表达，不依据孤立词语或标点作判断。围绕段落主命题整体重写，不逐个修补观察词。全文模式重点识别论文式引言重复、相关工作重复、重复段落模板、通用贡献或展望措辞、符号冲突和缺失过渡。

不得改变任何数字、引用键、`\todo`、`% src:` 注释、论断强度、不确定性、贡献归属或技术含义。不得仅为了显得像人而增加具体细节、个人观点或刻意的不规则表达。保留必要限定和有意修辞。报告超出语言编辑所有权的问题，并将其路由给负责的 skill。保持源文件一句一行。

编辑后将修订版与原文比较，恢复任何移动、丢失或被加强的受保护内容。运行 `bash execs/run.sh`，再运行 `bash execs/scpts/lint.sh --no-build`；正文警告只是建议项，必须按指南中的误报保护进行判断。把需要持续跟进的工作写成 `tasks/` 下的复选框。

`style` 模式可以更新 `notes/style.md` 而不编辑正文。该模式下，文件缺失时创建，并包含论文语言、作者声音、经作者确认的样本路径、句子与段落节奏、术语规则、缩写策略、章节开篇模式、过渡偏好、第一人称策略、限定语与论断强度习惯、标点习惯、需要保留的个人特征、跨章路标、引用风格和项目专用观察模式字段。论文语言使用 `en | zh`；其余字段留空或填写作者确认的自由文本，只有某项规则确认不存在时才使用 `none`。在同一次修改中创建 `notes/style.zh-CN.md`，且绝不能用骨架覆盖已有档案。
