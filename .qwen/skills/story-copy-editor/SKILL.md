# Copy-edit the thesis

**Shared conventions.** Read `docs/mds/story-workflow/writing-workflow-conventions.md` in full before acting. Read `.env` once for the `STORY_LANG`, `INVOLVE`, and `STORY_MAIN` values this run needs, and reuse them. Resolve the language of replies and new Markdown under conventions §7: an explicit author request first, then a valid `STORY_LANG`, then the dialogue language, or the invocation language when there is no user turn. Manuscript prose follows `degree/profile.tex`, and an existing file keeps its language. A clear instruction may select the target and scope and authorize the corresponding action within this skill's documented paths, and work already authorized in this run is not asked for again; it never replaces a confirmation point or an `AGENTS.md` §1 ask-first choice (conventions §7).

**Target.** Resolve one: a chapter, a front- or back-matter file the active entry point inputs, `full`, or `style`; with none, ask. Typing `full` confirms the whole-thesis pass (conventions §7, Authorization) over the chapters and the front and back matter the entry point inputs (conventions §5).

The human-writing contract (conventions §5) governs the run: read `notes/style.md`, where present, and the author-confirmed samples it names; never change a claim or its ledger row (conventions §3). A missing style profile does not block; a missing story, notation, or outline routes to its first creator (conventions §1).

A whole-thesis pass also looks for duplicated related work, conflicting notation, and missing transitions. For a notation conflict, ask the author which form is canonical, then apply it to the prose and its `notes/notation.md` row. At `low`, or when the author does not choose, change neither: route a conflict within one chapter to `story-chap-drafter`, and record a thesis-wide one as a `tasks/prose.md` line keyed by the term, for a later `full` pass to apply once the author confirms the form. Route anything else beyond prose to its owner (conventions §7, Ownership).

Build and lint (conventions §8). Write each durable follow-up as a checkbox line in the advisory `tasks/prose.md`, ticking any line this run resolves (conventions §6).

**`style`** updates `notes/style.md` without editing prose and never overwrites an existing profile with the scaffold. When the file is absent, create it with fields for manuscript language (`en | zh`, mirroring `% dissertation_language` in `degree/profile.tex`, which wins on conflict), authorial voice, author-confirmed sample paths, sentence and paragraph rhythm, terminology preferences (canonical terms live in `notes/notation.md`), acronym policy, chapter-opening pattern, transition preferences, first-person policy, qualification and claim-strength practice, punctuation practice, preserved quirks, cross-chapter signposting, citation style, and project-specific watch patterns. Every other field is empty or author-confirmed free text, and `none` marks only a confirmed absence of a rule. A request to profile a sample the author names confirms that sample's path, not the run's interpretation of it: record the path under author-confirmed sample paths, propose in the report the field wording the sample suggests, and write a field only once the author confirms that wording; at `low`, write no field from the sample, keep any field that already holds text, and say so in the report.
