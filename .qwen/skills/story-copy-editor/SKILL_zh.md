# 润色学位论文

首先完整阅读 `docs/mds/story-workflow/writing-workflow-conventions.md` 和 `docs/mds/story-workflow/human-writing-guide.md`。确定要润色的章节，或明确确认执行全文处理。`notes/style.md` 存在时读取，并读取 `notes/notation.md`、`notes/story.md` 和相关提纲简报。风格档案所列、经作者确认的风格样本也要读取。缺少风格档案不妨碍普通润色；缺少总叙事、符号表或提纲元数据时，路由给负责创建它的 skill。

编辑前标记受保护内容：事实、数字、日期、引文、引用键、来源注释、论断与不确定性边界、技术区别和归属。改进句式、段落衔接、路标、术语、缩写词引入和跨章节一致性。按模式组合和功能诊断公式化表达，不按孤立词语或标点判断。围绕段落主命题整体重写，不逐个修补观察词。全文处理时识别重复的论文式引言、重复的相关工作、反复出现的段落模板、通用的贡献或展望措辞、符号冲突和缺失的过渡。

不得改变任何数字、引用键、`\todo`、`% src:` 注释、论断强度、不确定性、贡献归属或技术含义。不得仅为了显得像人而增加具体细节、个人观点或刻意的不规则表达。保留必要的限定和有意的修辞。报告超出正文润色职责的问题，并路由给负责的 skill。保持源文件一句一行。

编辑后将修订版与原文比较，恢复任何移动、丢失或被加强的受保护内容。运行 `bash execs/run.sh`，再运行 `bash execs/scpts/lint.sh --no-build`；正文检查结果只作建议，须按指南中的误报保护判断。把需要持续跟进的工作写成 `tasks/` 下的复选框。

`style` 模式可以更新 `notes/style.md` 而不编辑正文。该模式下，若文件缺失则创建，字段包括论文语言、作者声音、经作者确认的样本路径、句子与段落节奏、术语规则、缩写策略、章节开篇模式、过渡偏好、第一人称策略、限定语与论断强度习惯、标点习惯、需要保留的个人习惯、跨章路标、引用风格和项目专用观察模式。论文语言使用 `en | zh`；其余字段留空或填写经作者确认的自由文本，`none` 仅用于标记某项规则确认不存在的情况。在同一次修改中创建 `notes/style.zh-CN.md`，绝不能用骨架覆盖已有档案。
